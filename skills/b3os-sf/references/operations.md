# 운영 — 감시, 장애, 정비, 피드백

내보낸 뒤에는 살아 있는지, 느려졌는지, 오류가 늘었는지를 자동으로 감시하고 이상을 알린다. 장애는 영향 제한과 되돌리기로 먼저 복구한 뒤 원인을 찾고, 수정은 개발 순환으로 되돌린다.

버그와 크래시는 수집 → 재현 → 수정 → 회귀 테스트 → 배포 → 실사용 확인 순환으로 다룬다. 의존성·런타임 정비는 백업 뒤 수행한다. 사용자 피드백과 새 요청은 `TODO.md`에 원문으로 기록해 같은 개발 순환에 넣는다.

롤백(직전 정상 버전으로 되돌리기)은 영향 제한이 먼저라 승인을 기다리지 않고 한 뒤 곧바로 팀장에게 보고한다. 롤백이 아닌 새 업로드·새 배포·재시작과 되돌릴 수 없는 복구(데이터 삭제·스키마 변경)는 승인 게이트를 따른다.

되돌리기 어려운 변경, 데이터·보안 영향, 출시 게이트 예외에는 사람 승인을 둔다. 운영 결과로 기능이 바뀌면 `FEATURES.md`, 구조가 바뀌면 `DESIGN.md`, 작업 근거는 `TODO.md`와 검증 근거 폴더를 갱신한다.

사용자에게 앱 조작(닫기·삭제·되돌리기)을 안내하기 전에 그 동작이 디스크·메타데이터에 하는 일을 코드로 확인한다. 데이터가 걸리면 가장 안전한 것(아무것도 하지 않기·되돌릴 수 있는 것)만 권하고, 확인 못 했으면 "건드리지 말고 고친 판을 기다려 달라"가 기본이다. 인프라·외부 서비스 작업 보고는 항목마다 "만든 것 · 용도 · 공개/비공개 · 남은 결정"을 한 줄씩 적는다.
