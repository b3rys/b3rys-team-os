# 운영 — 감시, 장애, 정비, 피드백

내보낸 뒤에는 살아 있는지, 느려졌는지, 오류가 늘었는지를 자동으로 감시하고 이상을 알린다. 장애는 영향 제한과 되돌리기로 먼저 복구한 뒤 원인을 찾고, 수정은 개발 순환으로 되돌린다.

버그와 크래시는 수집 → 재현 → 수정 → 회귀 시험 → 배포 → 실사용 확인 순환으로 다룬다. 의존성·런타임 정비는 백업 뒤 수행한다. 사용자 피드백과 새 요청은 `TODO.md`에 원문으로 기록해 같은 개발 순환에 넣는다.

되돌리기 어려운 변경, 데이터·보안 영향, 출시 게이트 예외에는 사람 승인을 둔다. 운영 결과로 기능이 바뀌면 `FEATURES.md`, 구조가 바뀌면 `DESIGN.md`, 작업 근거는 `TODO.md`와 검증 근거 폴더를 갱신한다.
