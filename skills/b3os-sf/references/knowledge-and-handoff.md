# 지식·종료 — 근거 축적과 인계

## 무엇을 어디에 쌓나

| 무엇 | 어디 | 다시 쓰는 사람 |
|---|---|---|
| 요청과 상태 | `TODO.md` | 출시 보고 도구와 PM |
| 되는 기능 | `FEATURES.md` | 새 팀원·리뷰어 |
| 구조 | `DESIGN.md` | 큰 변경의 설계·리뷰 |
| 검증 근거 | `docs/acceptance` 같은 프로젝트 폴더 | 검사·인수 담당 |
| 프로젝트 노하우 | 프로젝트 저장소의 노하우 문서 | 다음 작업 담당 |
| 팀 공통 교훈 | 공유 기록 → 주간 검토 → 공통 규칙 후보 | 모든 팀원 |
| 방법 자체 | `b3os-sf` | 프로젝트 담당 |

프로젝트 단계가 끝날 때마다 재사용 가능한 교훈을 갱신한다. 지식은 근거를 쌓고 반대 의견으로 검토한 뒤 채택 범위·조건·재확인 시점을 기록한다. 재확인 결과에 따라 유지·수정·폐기한다.

## 종료

`TODO.md`를 `[x]`, 칸반 카드를 `done`으로 맞추고 `FEATURES.md`, 배포·공증 링크와 검증 근거를 갱신한다. “다 처리했어?”에는 전체·완료·남은 수를 숫자로 답하고, 남은 이유와 못 잰 범위를 함께 적는다.

위임 뒤 대기는 `b3os-task-loop`의 `recheck_at`, `fallback`, `escalation_after`를 쓴다. 배달 성공이 아니라 답장이 착수 신호다. 리듬을 넘기면 팀장에게 알린다.

## 인계 네 줄

1. 지시 요지
2. 진행 여부
3. 저장소·브랜치 기준점
4. 맡길 범위와 완료 기준

브랜치 기준점과 범위를 빠뜨리지 않는다. 병합 보고에는 잰 것과 안 잰 것을 적고, 확인하지 않은 것은 통과로 세지 않는다.
