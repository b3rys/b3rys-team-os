# AI 팀 코딩 지침

이 지침은 특정 앱이나 플랫폼에 묶이지 않는다. 각 원칙은 기능을 만들 때 바로 확인할 수 있는 행동으로 쓴다.

용어를 먼저 푼다.

- **토큰량:** AI가 읽고 쓰는 텍스트를 세는 단위의 양.
- **자기 타입:** 한 기능의 데이터와 동작을 맡는 전용 코드 구조.
- **언어 표:** 같은 화면 문구를 지원 언어별로 모아 둔 파일.
- **비동기:** 오래 걸리는 일을 화면을 멈추지 않고 따로 실행하는 방식.
- **리터럴:** 설정 파일이나 언어 표가 아니라 코드에 직접 쓴 숫자·경로·문구.

## 1. 새 기능은 자기 타입과 자기 설정 파일에 둔다

- **원칙:** 새 기능을 공용 클래스에 조건문으로 붙이지 않는다.
- **왜:** 사례: 수집 중. 예: 새 실행 도구는 도구 타입과 도구 설정 파일을 만들고 공용 화면에는 목록만 전달한다.
- **어떻게:** 변경 파일 목록에서 새 기능 전용 타입·설정 파일이 있는지, 공용 클래스에 기능 이름 조건문이 늘지 않았는지 확인한다.

## 2. 구조화해 고친 곳만 검사한다

- **원칙:** 기능 경계를 나누면 고친 모듈 검사로도 품질을 지킬 수 있다.
- **왜:** 예: 개발 배포 검사는 변경 파일 매핑과 자동 재검사 중지 뒤 19분에서 4분 46초로 줄었다.
- **어떻게:** 기능을 일부러 고장 낸 코드로 시험이 잡는지 확인한다. 이 코드를 뮤턴트라고 한다.

## 3. 변경 파일로 검사 4단계를 자동 선택한다

- **원칙:** 검사를 사람이 기억해서 고르지 않고 변경 파일 표가 고른다.
- **왜:** 사례: 수집 중. 예: 문서 파일만 바꿨다면 문서 링크 검사부터 돌리고, 전체 제품 검사는 출시 단계에서 돌린다.
- **어떻게:** [`dev-mode-operations.md`의 검사 4단계와 선택 방법](dev-mode-operations.md#변경-파일로-자동-선택하는-검사-4단계)을 따른다.

## 4. 리팩터링은 목표가 아니라 신호에 대한 대응이다

- **원칙:** 개발 모드의 검사표에서는 기능 하나 때문에 검사가 3단계까지 올라갈 때만 구조 변경을 제안한다.
- **왜:** 사례: 수집 중. 예: 작은 기능이 공용 파일을 건드려 연관 기능 검사까지 요구하면 경계가 섞였다는 신호다.
- **어떻게:** 검사 표가 3단계를 고른 이유를 기록하고, 기능 전용 타입·설정으로 분리할 수 있는지 검토한다. 수정 집중·시험 교차 실패 같은 일반 구조 신호는 [`development.md`](development.md#구조-가드)를 따른다.

## 5. 기능 머지마다 짧게 구조를 검토한다

- **원칙:** 기능을 합치기 전에 자리·분기·중복만 짧게 본다.
- **왜:** 사례: 수집 중. 예: 새 기능의 조건문이 공용 진입점 세 곳에 생겼다면 합치기 전에 입구를 하나로 모은다.
- **어떻게:** PR에 “제자리인가, 새 분기가 생겼나, 같은 값의 입구가 둘 이상인가” 세 질문의 답을 남긴다.

## 6. 화면 문구는 언어 표에서 관리한다

- **원칙:** 사용자에게 보이는 문구를 코드에 직접 쓰지 않는다.
- **왜:** 사례: 수집 중. 예: 버튼 문구를 언어 표에 두면 한국어·영어 누락을 한 검사에서 잡을 수 있다.
- **어떻게:** 소스의 화면 문구 리터럴을 금지하는 검사와 언어 표의 모든 지원 언어 칸 검사를 머지 조건으로 둔다.

## 7. 설정값은 코드가 아니라 설정 파일에 둔다

- **원칙:** 시간·크기·경로·기능 켜짐 같은 운영값을 코드에 박지 않는다.
- **왜:** 사례: 수집 중. 예: 검사 제한 시간을 설정 파일에 두면 환경별 값을 코드 변경 없이 조정할 수 있다.
- **어떻게:** 새 숫자·경로가 코드에 생기면 설정 파일에 둘 값인지 검토하고, 개발·시험·출시 환경 값을 분리한다.

## 8. 사이드 이펙트는 조건문이 아니라 구조로 막는다

- **원칙:** 한 기능 수정이 다른 기능을 깨뜨리면 예외 조건을 덧대지 말고 경계를 나눈다.
- **왜:** 사례: 수집 중. 예: 화면을 그리는 중 상태를 바꾸지 않고, 탐색은 비동기로 실행한 뒤 결과만 화면에 전달한다.
- **어떻게:** 한 구역을 일부러 고장 냈을 때 다른 구역 시험이 깨지는지 확인하고, 깨지면 상태·입구·설정의 소유자를 분리한다.
