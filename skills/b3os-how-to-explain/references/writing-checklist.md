# 쓸 때 채우는 칸과 보내기 전 훑는 것

SKILL.md 의 규칙이 "무엇을 지킬 것인가" 라면 이 문서는 "빈 화면에서 어떻게 시작할 것인가" 다.
gd-el10 스킬(2026-09-08 폐지)에서 이 스킬로 옮겨온 부분이며, SKILL.md 본문과 겹치지 않는 것만 남겼다.
아래 R0~R7 번호는 폐지된 gd-el10 의 규칙 번호다. 그 문서는 더 이상 없으므로 번호는 이 파일 안에서만 참조한다.

## ★쓰는 순서★ — 이것만 보고 써도 된다

**규칙을 외우고 쓰는 게 아니다. 이 다섯 칸을 순서대로 채운다.**

```
1줄     ★무엇에 대한 얘긴가★    이 메시지의 제목. 이게 없으면 나머지가 안 읽힌다
1줄     등장하는 게 뭔가        처음 나오는 이름에 한 줄 정의
1줄     어떤 경우인가           이 얘기가 성립하는 조건
3~6줄   단계                   각 줄에 그때의 실제 값 (시각·경로·값·출력)
1줄     그래서 뭐가 달라지나     상대 입장에서
[있으면] 상대가 할 일           ★누가 · 무엇을 · 언제★ 를 실제 값으로
[선택]  확인한 것 / 못 한 것
```

채운 예:

```
같은 일이 두 번 실행되던 것을 고쳤습니다.          ← 무엇에 대한 얘긴가
일을 맡기면 "이건 A 가 맡았다" 고 적어두는데,
그 표시에 만료 시각이 붙는다.                     ← 등장하는 게 뭔가

어떤 경우 — A 가 10분 넘게 걸리는 일을 하는 중      ← 어떤 경우인가

1. 11:00:00  A 가 맡음 → "11:11:00 까지 A 것"      ← 단계
2. 11:11:00  만료. 그런데 A 는 아직 일하는 중
3. 11:11:30  B 가 같은 일을 집어감

이제 A 가 출력할 때마다 만료가 밀려서 3 이 안 일어납니다.  ← 뭐가 달라지나
```

**상대가 할 일이 있으면 마지막 칸을 비우지 마라.** "확인 부탁드립니다" 는 할 일이 아니다.
```
✗  확인 부탁드립니다
✓  리뷰어가 오늘 안에 확인 → 통과하면 제가 머지합니다. 요청자는 안 하셔도 됩니다.
```
**누가·무엇을·언제가 없으면 보고가 거기서 멈춘다.**

**칸을 빼도 되는 때**:
- 질문에 답하는 것이면 **맨 앞에 판정(예/아니오)을 먼저** 놓는다 (R0)
- 기능·버그 얘기가 아니면 `어떤 경우`·`단계` 칸은 없어도 된다. 나머지 셋은 항상 있다
- 상대가 할 일이 없는 단순 보고면 **1~2줄로 끝낸다** (R4)

**어느 칸이 어느 규칙인가** — 그 칸이 안 써지면 그 규칙만 읽으면 된다:

| 칸 | 규칙 |
|---|---|
| 무엇에 대한 얘긴가 | **R1** 내가 한 일이 아니라 상대가 겪은 일·물은 것·정할 것 |
| 등장하는 게 뭔가 | **R2** 원어 그대로 + 실물 한 줄. 정의의 재료도 아는 말로 |
| 어떤 경우 · 단계 | **R6** 한 건을 골라 시간순으로. 값 없는 번호는 효과 없음<br>**정적 구조**(아키텍처·구성)는 시간순 대신 **입력 → 처리 주체 → 출력** |
| 전체 길이 | **R4** 상대가 할 일에 비례 |
| 뺄 것 | **R5** 이미 정해진 절차는 결과만 |
| 값으로 쓸 것 | **R3** 비유 말고 실제 값 |
| 보내기 전 | **R7** 일곱 가지 훑기 |

## 규칙 여덟 — 한 줄씩

**맨 위 핵심 셋을 채우는 법이다.** 전부 외울 필요 없다.
막히는 칸이 있으면 `references/rules-detail.md` 에서 그 규칙만 편다.

| | 규칙 | 한 줄 |
|---|---|---|
| | **R1** | 첫 줄은 **상대가 겪은 일·물은 것·정해야 할 것**. 내가 한 일로 시작하면 "무슨 얘기야" 가 온다 |
| | **R2** | 용어는 **원어 그대로 + 한 줄 정의**. 대상은 **이 대화 밖에서 상대가 모를 이름**뿐 — 익숙한 제품명까지 풀면 길어지기만 한다 |
| | **R3** | 비유 말고 **실제 값** — 단 **판단에 필요한 것만**. **확인 안 한 것은 추정이라고 표시** |
| 보완 | R0 | **질문에 답하는 것**이면 판정(예/아니오)을 첫 줄에 |
| 보완 | R4 | 길이는 **상대가 할 일**에 비례. 줄일 것은 분량이 아니라 세부 |
| 보완 | R5 | **이미 정해진 절차**는 결과만. 용어는 풀고 절차는 뺀다 |
| 보완 | R6 | **기능·버그**는 한 건을 시간순으로. 값 없는 번호는 효과 0 (실측). **정적 구조는 입력→처리→출력** |
| 보완 | R7 | 보내기 전 훑기 — 아래 아홉 가지 |

### 보내기 전 훑는 것 (아홉)

1. **이게 무엇에 대한 얘기인지 첫 줄에 있나** ← 가장 자주 빠진다
2. **상대가 이걸 알아야 하나** — 아니면 내 작업 내역인가
3. 상대가 이 대화 밖에서 본 적 없는 **명사**에 정의가 있나
4. **"됐습니다/안 됐습니다" 인데 값이 없는 문장**이 있나
5. 첫 줄이 **내가 한 일**로 시작하나
6. 상대가 할 일이 없는데 **10줄이 넘나**
7. 처음 나오는 **이름이 셋 이상**인가 → 나눠 보낸다
8. 기능·버그 얘기인데 **시퀀스가 없나**
9. **예문·인용을 내 작업 보고와 섞지 않았나** → 섞으면 상대는 그것도 내가 한 일로 읽는다

**이 한 번이 핑퐁 한 번보다 싸다.**

## 강조는 강조를 못 한다 (실측)

2026-08-20~22 팀 버스 메시지 실측:

```
메시지당 평균 ★ 개수 :  팀원 A 53.1  ·  팀원 B 31.5
1500자 넘는 메시지   :  팀원 A 118건 ·  팀원 B 85건
```

한 메시지에 강조가 53개면 **강조한 것이 없는 것과 같다.** 눈이 어디에 멈춰야 할지 모른다.
읽는 쪽에서 "너무 길어 보기 힘들다" 는 지적이 여기서 나온다.

**한 메시지에 강조는 많아야 두세 개** — 상대가 그것만 읽어도 결론이 서는 문장에만.

## 자주 나오는 유혹

**"짧게 쓰라니까 요약해야지"** → 요약이 아니라 **덜 중요한 걸 빼는 것**이다.
추상화하면 짧아지지만 되묻힌다. 실제 값은 남기고 곁가지를 뺀다.

**"용어를 풀어 써야 친절하지"** → 푸는 것과 **바꿔치기**는 다르다.
`lease` 를 "예약" 으로 **대체**하면 안 되고, `lease` 를 쓰면서 **옆에 한 줄** 붙이는 게 맞다.

**"비유를 들면 이해가 빠르지"** → 비유**만** 주면 빠른 건 **이해한 느낌**이지 이해가 아니다.
실제 이름·값을 준 뒤 곁들이는 건 괜찮다. **대신하지만 마라.**

**"과정을 다 보여줘야 신뢰가 가지"** → 상대가 원하는 건 과정이 아니라 **지금 상태**다.
과정은 카드·PR 본문에 남긴다.

**"내가 고생한 걸 알려야지"** → 그건 내 사정이다. 설명은 **상대가 할 일**을 위해 쓴다.
