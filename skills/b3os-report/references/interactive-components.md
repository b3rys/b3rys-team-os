# 인터랙티브 컴포넌트 — 보고서 안에서 직접 움직여 보는 그림

글과 그림만으로는 "값을 바꾸면 무엇이 바뀌나"가 잘 안 보인다. 슬라이더를 움직이거나 단계를 넘겨 보면 그 관계가 바로 보인다.
이 절은 보고서 안에 그런 조작 화면을 넣는 규약이다. 공용 부품은 `assets/components/` 에 있고, 렌더러가 본문에 쓰인 것만 골라 넣는다.

## 언제 쓰나

- ✅ **값 하나를 바꾸면 결과가 연속으로 바뀌는 관계** — 비트 수 → 오차, 금리 → 채권 가격, 문장 길이 → attention 계산량
- ✅ **단계를 하나씩 넘겨 봐야 이해되는 과정** — 토큰이 층을 지나는 순서, 차트에서 이동평균선이 교차하는 시점
- ✅ **독자가 자기 숫자를 넣어 보고 싶은 계산** — PER·ROE·PBR 관계
- ❌ 정적 표나 그림 한 장으로 충분한 것 — 움직여도 새로 알게 되는 게 없으면 넣지 않는다
- ❌ 장식용 애니메이션

보고서 하나에 1~3개. 각 컴포넌트는 본문의 특정 문단 하나를 돕는다 — 그 문단 바로 아래에 둔다.

## 쓰는 법 (MD 안)

```html
<b3-예시 class="ix" data-…="…">
  <div class="ix-title">비트 수를 줄이면 무엇이 달라지나</div>
  <svg …>스크립트 없이 보일 기본 상태 그림</svg>
  <p class="ix-caption">이 그림이 무엇을 보여 주는지 한두 문장.</p>
  <p class="ix-note">새창보기(↗)로 열면 직접 조작할 수 있습니다.</p>
</b3-예시>
```

- 태그 이름은 `b3-` 로 시작한다. 렌더러가 `assets/components/<태그>.js` 를 찾아 그 보고서에 넣는다. 파일이 없으면 렌더가 실패한다.
- 블록은 줄 맨 앞의 `<b3-…>` 로 시작해 `</b3-…>` 로 닫는다(렌더러가 원문 그대로 통과시킨다). 안에 빈 줄을 두지 않는다.
- 입력 값은 `data-*` 속성이나 안쪽 `<script type="application/json" class="ix-data">` 에 둔다. **숫자는 보고서 본문에 이미 있는 값과 공식만** 쓴다. 설명용으로 지어낸 값이면 캡션에 "설명용 예시 값" 이라고 적는다.

## 스크립트가 막힌 곳에서도 읽혀야 한다

`/reports` 포털 미리보기는 보고서를 `sandbox` iframe 으로 띄워 **스크립트가 돌지 않는다**(`render.mjs` 탭 주석). 새창보기·텔레그램 첨부·파일로 직접 열 때만 돈다.

- 태그 안쪽 내용 = **정적 기본 상태**. 스크립트가 없어도 그림과 캡션으로 요점이 전달돼야 한다.
- `.ix-note` 는 컴포넌트가 정의되지 않았을 때(`:not(:defined)`)만 보인다. 스크립트가 돌면 저절로 숨는다.
- 스크립트가 돌면 컴포넌트가 정적 내용을 조작 화면으로 바꾼다. 제목(`.ix-title`)은 그대로 둔다.

## 컴포넌트 파일 (`assets/components/b3-이름.js`)

- 의존성 없는 순수 JS. `customElements.define('b3-이름', class extends HTMLElement {…})`. 같은 이름이 이미 정의돼 있으면 건너뛴다.
- Shadow DOM 을 쓰지 않는다 — 보고서 테마(`--ink`·`--green`·`--line` 등 CSS 변수)와 공용 클래스(`.ix-*`)를 그대로 받아야 다크·라이트 전환이 저절로 맞는다.
- 컴포넌트 전용 CSS 가 필요하면 JS 가 `document.head` 에 `<style data-b3="이름">` 을 **한 번만** 넣고, 선택자는 태그 이름으로 시작한다(`b3-이름 .bar{…}`).
- SVG 색은 `fill="#…"` 하드코딩 대신 `style="fill:var(--green)"` 또는 클래스로 — 테마가 바뀌면 같이 바뀐다.
- 네트워크·`localStorage`·외부 글꼴·외부 라이브러리 금지. 보고서는 자체완결 파일이다.
- 아이폰 폭(390px)에서 손가락으로 조작된다: 버튼·슬라이더 높이 32px 이상, 가로 넘침 0, 글자 13px 이상.
- 키보드로도 조작된다: 버튼은 `<button>`, 슬라이더는 `<input type="range">` + `aria-label`, 결과 영역은 `aria-live="polite"`.
- 숫자 계산은 컴포넌트 안에 공식으로 둔다. 정적 기본 상태의 숫자와 스크립트가 처음 그린 숫자가 같아야 한다.

공용 클래스(`components.css`): `.ix` 틀 · `.ix-title` · `.ix-row` · `.ix-label` · `.ix-value` · `.ix-strong`/`.ix-warn`/`.ix-bad` · `.ix-btn`(`aria-pressed="true"` 이면 켜짐) · `.ix-seg` · `.ix-caption` · `.ix-note`.

## 배포 전 검사

`render.test.mjs` 는 구조만 본다. 컴포넌트가 들어간 보고서는 브라우저에서 이것을 잰다.

1. 폭 3개(1440·900·390) × 다크·라이트 — 콘솔 오류 0, 가로 넘침 0
2. 스크립트를 끈 상태(포털 미리보기와 같은 조건) — 정적 그림·캡션·안내가 보이고 빈 상자가 없다
3. 조작 한 번씩 — 슬라이더 끝값·버튼 전부를 눌러 숫자가 본문과 맞는지
4. WebKit 에서 한 번(아이폰 사파리와 같은 엔진, 사파리 앱 자체 검증은 아니다)
