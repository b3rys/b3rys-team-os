# 설명그림 (explanation diagram) 작성 규칙

> 보고서·교육 컨텐츠에 넣는 다이어그램을 "장식"이 아니라 **그림만 봐도 개념이 잡히는 설명 수단**으로 만드는 규칙.

## 1. 두 종류를 구분한다

| | 장식 그림 | 설명그림 |
|---|---|---|
| 그림을 빼면 | 글만으로 같은 이해에 도달한다 | 글만으로는 이해가 안 된다 |
| 그림 안 글자 | 이름표만 (`Encoder`, `DB`) | 이름표 + 그 옆에 하는 일 한 줄 |
| 값 | 없거나 임의 | 실제 값 또는 "설명용 예시" 표시 |
| 읽는 순서 | 아무 데서나 | ①②③ 번호나 화살표로 정해져 있다 |

보고서에는 **설명그림만** 넣는다. 장식 그림은 넣지 않는 편이 낫다 — 독자의 시선을 뺏고 아무것도 주지 않는다.

판별 질문 하나: **이 그림만 보고 개념을 남에게 설명할 수 있나?** 못 하면 아직 장식이다.

## 2. 예 하나를 문서 끝까지 끌고 간다

설명그림이 잘 읽히는 가장 큰 이유는 그리는 기술이 아니라 **같은 예가 그림마다 이어지는 것**이다.

- 문서 맨 앞에서 예를 하나 정하고, 마지막 그림까지 그 예를 쓴다.
- 그림 N 의 출력이 그림 N+1 의 입력이 되게 배치한다.
- 다른 예가 꼭 필요하면(대조를 보여줘야 할 때 등) 그 자리에서만 쓰고, 왜 다른 예를 쓰는지 한 줄 적는다.

**실제 적용 예** — `/reports/file/llm-book/html` 의 0부는 문장 하나(`고양이가 배가 고파서 그것이 울었다`)로 그림 13장을 이었다.

```
그림 1  문장    → 토큰 12개 + 토큰 번호
그림 2  토큰 번호 → 배열 4,096개
그림 3  같은 문장으로 "순서를 안 넣으면 왜 안 되나"
그림 4  같은 문장의 "그것이" 자리에서 다섯 단계 계산 → 실제 값
그림 5  같은 네 토큰의 비율을 4×4 표로
...
그림 13 같은 문장의 번역을 encoder-decoder 로
```

예가 바뀌면 독자가 매 그림에서 처음부터 다시 이해해야 한다. 그림 수가 늘수록 손해가 커진다.

## 3. 그림 안에 값을 넣는다

### 실제 값을 쓴다

그림에 넣을 숫자는 **글쓴이가 직접 돌려서 얻는다.** 계산이 필요하면 짧은 스크립트를 짜서 돌리고, 그 스크립트를 문서 부록에 같이 싣는다. 독자가 그대로 재현할 수 있어야 한다.

### 지어낸 값은 그 자리에 표시한다

설명하려고 값을 정해야 할 때가 있다. 그때는 **그림 안에** 적는다 — 캡션이 아니라 그림 안이다. 독자가 그림만 잘라서 보기도 한다.

```
✓  <text class="diagram-muted">위 숫자는 설명용 예시다. 실제 값은 층·head 마다 다르다.</text>
✗  캡션에만 "예시" 라고 적고 그림 안에는 숫자만
```

### 들어갈 때와 나올 때를 같이 보여준다

계산을 설명하는 그림은 **before / after 를 한 화면에** 둔다. 이 두 줄이 그림의 결론이다.

```
들어감  [0.0, 0.0, 1.0, 0.4]   ← 이 정보가 없다
나옴    [0.707, 0.202, 0.092, 0.160]   ← 이 정보가 들어왔다
```

## 4. 여섯 가지 틀

대부분의 설명그림은 아래 여섯 중 하나다. 새 구조를 발명하기 전에 여기서 고른다.

### ① 파이프라인 — 단계마다 값이 바뀔 때

세로로 단계를 쌓고, 각 단계 오른쪽에 그 단계의 **결과 값**을 둔다. 단계 사이는 화살표.
왼쪽에 단계 이름 + 한 줄 설명, 가운데 값, 오른쪽에 "왜 이 단계가 필요한지" 한 줄.

### ② 행렬 — 관계가 표로 떨어질 때

행·열에 이름을 붙이고 칸에 값을 넣는다. 값의 크기는 `opacity` 로 나타낸다.
비어 있는 칸은 빈칸으로 두지 말고 `—` 를 넣고, 그 뜻을 옆에 적는다.

```html
<rect class="diagram-accent" opacity=".679"/>
```

### ③ 막대 비교 — 크기 차이가 요점일 때

값 그대로가 아니라 **비율**이 보이게 그린다. 막대 끝에 실제 숫자를 붙인다.
막대 길이는 최대값이 컨테이너 폭의 60~70% 를 넘지 않게 잡는다(숫자 자리를 남긴다).

### ④ 구조 스택 — 무엇이 무엇 안에 있는지

왼쪽에 전체 흐름, 오른쪽에 그중 하나를 확대. 세로선(`diagram-line`)으로 두 영역을 나눈다.
확대한 쪽에는 실제 크기 값을 적는다(`4,096 → 14,336 → 4,096`).

### ⑤ 대조 — "있을 때 / 없을 때"

세로선으로 좌우를 나누고 같은 높이에 같은 요소를 둔다. 눈이 가로로 비교한다.
좌우 제목은 같은 문법으로 쓴다 (`residual 없이 — 층이 값을 갈아치운다` / `residual — 층이 더할 값만 정한다`).

### ⑥ 반복 단계 — 같은 것이 여러 번 돌 때

같은 모양의 행을 세로로 3~4개 쌓고, 회차마다 **달라지는 부분만** 강조색을 준다.
마지막에 "여기서 멈춘다" 같은 종료 조건을 적는다.

## 5. 팔레트·class 규칙

**하드코딩 색을 쓰지 않는다.** `#0b0f14` 같은 값을 SVG 에 적으면 라이트 모드에서 글자가 안 보인다.
`class="diagram-flow"` 를 루트 `<svg>` 에 주고, 아래 class 만 쓴다.

| 용도 | class |
|---|---|
| 기본 상자 | `diagram-node` |
| 강조 상자 (초록) | `diagram-node-primary` |
| 보조 강조 (금색) | `diagram-node-warm` |
| 문제·차단 (빨강) | `diagram-node-danger` |
| 막대·채움 | `diagram-accent` · `diagram-accent-warm` · `diagram-accent-danger` |
| 본문 글자 | `diagram-text` (13px) |
| 설명 글자 | `diagram-muted` (11px) |
| 작은 제목 | `diagram-title` |
| 선·화살표 | `diagram-line` · `diagram-line-primary` · `diagram-line-warm` |

색으로 의미를 나눌 때는 **그림 안에 범례 한 줄**을 적는다 — `초록 = 지금 처리 중 · 빨강 = 막힌 자리`.

### 화살표 marker

`marker` 의 `id` 는 **문서 안에서 고유해야 한다.** 한 페이지에 SVG 가 여러 개면 같은 id 가 충돌해 화살표가 사라진다. 그림마다 접두어를 붙인다.

```html
<defs><marker id="m5s" markerWidth="8" markerHeight="8" refX="6" refY="3" orient="auto">
  <path d="M0,0 L6,3 L0,6 Z" class="diagram-accent"/>
</marker></defs>
<path d="M371 68 L371 82" class="diagram-line" marker-end="url(#m5s)"/>
```

## 6. 모바일 대체 카드

가로로 넓은 그림은 iPhone 에서 축소되면 글자를 못 읽는다. 같은 `<figure>` 안에 **모바일 카드를 함께** 둔다. 테마가 640px 에서 자동으로 바꾼다.

```html
<figure>
<figcaption>그림 N · 한 줄 설명</figcaption>
<div class="mobile-infographic" role="group" aria-label="요약">
  <div class="mi-card mi-green"><h4>① 단계 이름</h4><p>그 단계의 결과를 값으로</p></div>
  <div class="mi-card mi-amber"><h4>② 단계 이름</h4><p>…</p></div>
</div>
<svg class="desktop-infographic diagram-flow" viewBox="0 0 760 320" role="img" aria-label="…">…</svg>
</figure>
```

카드는 그림의 요약이 아니라 **같은 정보를 세로로 푼 것**이다. 그림에 있는 실제 값을 카드에도 넣는다. 카드만 보고도 절의 내용이 서야 한다.

기본 class 는 `mi-green` · `mi-amber` · `mi-orange` · `mi-red` 다.

## 7. 레이아웃 실무

**viewBox** — 폭은 `760` 을 기본으로 쓴다(본문 960px 컨테이너 안에서 여백이 맞는다). 높이는 내용에 맞춘다.

**글자 폭 어림** — SVG `<text>` 는 자동 줄바꿈이 없다. 상자 밖으로 넘치면 그대로 잘린다.

| 글자 | 크기 | 글자당 폭 |
|---|---|---|
| 한글 | 11px (`diagram-muted`) | 약 11px |
| 한글 | 13px (`diagram-text`) | 약 13px |
| 영문·숫자 | 11px | 약 5.5px |

상자 폭 = 글자 수 × 위 값 + 좌우 여백 24px. 넘칠 것 같으면 **문장을 나눠 두 `<text>` 로** 쓴다. 한 `<text>` 에 긴 문장을 넣지 않는다.

**정렬** — 값이 여러 개 나란히 놓이면 `text-anchor="middle"` 로 상자 중앙에 맞춘다. 라벨은 `text-anchor="end"` 로 오른쪽 정렬해 값 열과 간격을 고정한다.

**영역 나누기** — `<line class="diagram-line">` 으로 나눈다. 세로선은 좌우 대조, 가로선은 "여기까지가 계산, 아래가 결론".

## 8. 그림 하나 끝낼 때 검사 목록

렌더한 HTML 을 **브라우저로 열어서** 확인한다. 소스만 보고 통과시키지 않는다.

- [ ] 라이트 모드에서 모든 글자가 읽히나 (하드코딩 색이 남아 있으면 여기서 걸린다)
- [ ] 다크 모드에서 모든 글자가 읽히나
- [ ] 상자 밖으로 넘친 글자가 없나
- [ ] 640px 폭에서 모바일 카드로 바뀌나, 카드만 봐도 내용이 서나
- [ ] 화살표가 전부 보이나 (marker id 충돌 확인)
- [ ] 그림 안 숫자가 본문·표의 숫자와 같나
- [ ] 지어낸 값에 "설명용 예시" 표시가 그림 안에 있나
- [ ] 이 그림만 보고 개념을 설명할 수 있나
- [ ] 앞 그림과 같은 예를 쓰고 있나
