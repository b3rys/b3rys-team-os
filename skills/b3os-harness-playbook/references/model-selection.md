# 작업별 모델 선택과 프론티어 갱신

## 운영 원칙

개발 품질을 우선하면서 일반 작업의 고가 모델 사용을 줄인다. 구형 모델이 항상 저렴하지 않으며, API 단가와 구독 한도는 다르다. 부모 모델을 상속한 실행을 작업별 모델 선택의 성공으로 기록하지 않는다.

## 도입 대상 매핑

다음은 도입 대상이지 모든 런타임에 설치·검증됐다는 선언이 아니다. 정확한 API 모델 ID와 effort 지원은 실행 전 확인한다.

| 작업 | Anthropic 후보 | OpenAI 후보 | effort |
|---|---|---|---|
| 단순 수집·정형 처리 | Sonnet 5.5 | GPT-6 Sol | low |
| 일반 개발·테스트·리뷰 | Sonnet 5.5 | GPT-6 Sol | high |
| 일반 문서·요약 | Sonnet 5.5 | GPT-6 Sol | medium |
| 복잡·고위험 판단·검증 | Opus 5.5 | GPT-6 Astra | high |

Opus high와 Astra high는 역할의 대응이지 벤치마크 동등성 선언이 아니다. xhigh/max는 실패 분석 뒤 예외 적용한다. mini/Haiku 등 더 낮은 티어는 개발 기본값에 자동 편입하지 않는다.

## 활성화 게이트

1. 공식 모델 문서에서 실재 모델 ID, provider 경로, effort 지원, 도구·구조화 출력·컨텍스트 지원을 확인한다.
2. 공식 가격표에서 입력·캐시 입력·출력·추론 토큰 과금·장문 할증·확인일을 남긴다. 구독은 실제 한도와 사용 가능 여부를 별도로 남긴다. ChatGPT 구독 로그인으로 도는 런타임(codex·openclaw)에서는 그 모델을 실제로 고를 수 있는지 따로 확인한다 — API 카탈로그에 있다는 것만으로 구독에서 쓸 수 있다고 보지 않는다. 이전 채팅의 가격표를 검증 없이 복사하지 않는다.
3. 같은 코드와 완료 조건으로 기능 구현·재현 버그·코드 리뷰를 평가한다. 고위험 과제에는 보안·동시성 검증을 추가한다.
4. 첫 검증 통과, 재작업, 누락 결함, 완료 시간, 작업당 전체 토큰/비용을 비교한다. 생성 토큰 단가만으로 결정하지 않는다.
5. 실행 로그의 실제 모델과 요청 모델을 대조한다. 별칭(`sonnet`·`opus` 등)으로 요청했으면 별칭이 풀린 실제 모델 ID 를 기록한다. effort가 응답에서 관측되지 않으면 요청 설정 확인과 실제 적용 확인을 구분한다.
6. 리뷰 후 런타임별 매핑을 적용한다. 변경 전 매핑을 남겨 복구 가능하게 한다. 검증 전에는 기존 모델을 유지하고 `candidate`로 표시한다.

## 프론티어 출시 시 갱신

- 담당: 서비스·전략 담당자가 공식 출시·가격·지원 변화를 확인하고, 개발 담당자가 실제 과제 품질을 검증한다.
- 주 1회 정기 점검으로 출시를 발견한다. 출시 즉시 감지하는 webhook이라고 표현하지 않는다. 별도로 새 출시 정보를 받으면 다음 점검까지 기다리지 않고 재평가한다.
- 출처: Anthropic 공식 모델/가격/출시 문서, OpenAI 공식 모델/가격/출시 문서. 검색 요약이나 제3자 표만으로 매핑을 확정하지 않는다.
- 새 출시뿐 아니라 가격 변경·지원 종료·effort/도구 지원 변경도 재평가 트리거다.
- 변화가 없으면 날짜·확인한 출처만 내부 기록하고 팀장에게 반복 보고하지 않는다.
- 변화가 있으면 현재 매핑과 후보의 차이, 검증 결과, 비용/품질 영향, 적용 여부, 롤백을 하나의 변경 요청으로 작성한다.
- 검증 없이 자동 모델 교체·게이트웨이 재시작·공유 설정 변경을 하지 않는다. 인증/한도 실패는 승격으로 우회하지 않는다.
- 점검 실패 시 미확인으로 기록한다. 연속 두 번 실패하면 담당자에게 알리고 마지막 검증 매핑을 유지한다.
- 운영 기록은 환경별로 보관한다: `checked_at`, `sources`, `candidate_model_id`, `provider`, `effort_support`, `pricing_basis`, `benchmark_result`, `decision`, `previous_mapping`, `review_status`.

## Hermes 실행 제약

현재 도구 스키마의 delegate_task에 개별 model/effort 인자가 없으면 config의 delegation 설정 또는 부모 상속이 적용된다. 문서 수정은 자동 라우터 구현이 아니다. 일반 개발을 Sol로 실행하려면 지원되는 명시 모델 CLI 등 별도 실행 경로를 검증하거나 적합한 팀원에게 위임한다. 글로벌 delegation을 중간에 바꿔 고위험 작업까지 저가 모델로 보내지 않는다.
