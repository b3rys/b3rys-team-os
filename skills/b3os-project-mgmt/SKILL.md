팀장님 (2026-09-10): "팀원이 단순 리서치, 프로토가 아니고 ★프로젝트★를 할 때, 항상 해야 되는 관리 및 보고 스킬인거지."
팀장님 (2026-09-10): "내가 주는 수정사항이 많으니 목록 및 진행으로 관리해." · "정리하면 텔레그램으로 보여주고."

## 언제 작동?
- 팀장 요구가 ★여러 번 쌓이는 일★ — 앱·서비스·긴 기능. 단발 리서치·프로토는 대상 아님 (그건 `b3os-task-loop` 카드 하나로 충분).
- "목록으로 관리해" · "정리해서 보내봐" · "다 처리했어?" · "지금까지 나온 말로 정리하자".
- 킥오프 · 마일스톤 · 공증본/배포 전달 · 다른 팀원에게 인계.

## 정본은 둘, 뷰는 여럿 (팀장 2026-09-10: "칸반, TODO.md 가 원본이고 그걸 기반으로 뷰를 하는 거지")

| 무엇 | 정본 | 어디 |
|---|---|---|
| 팀장 지시·결함·킵 목록 | `TODO.md` | ★프로젝트 저장소 루트★ (git 동기화) |
| 과제 상태 (plan/doing/done) | 칸반 `task` 카드 | `team.db` (`b3os-task-loop`) |
| 채널 보고 | 위 둘에서 만든 ★뷰★ | 텔레그램·슬랙·팀버스 |

★같은 사실을 두 곳에 다른 값으로 적지 않는다.★ 보고문을 손으로 고쳐 쓰다 TODO.md 와 어긋나면 정본이 둘이 된다. 보고는 TODO.md 를 읽어 만든다.

## 목록 규율 — 팀장이 말한 것은 ★전부★ 들어간다

1. 팀장 메시지 하나 = 항목 하나 이상. ★원문을 그대로 인용★해 붙인다 (요약본만 남기면 나중에 "이게 무슨 얘기야" 가 된다). 시각(KST)·msg id·사진 경로를 적는다.
2. 상태는 셋 — `[ ]` 미착수 · `[~]` 진행중 · `[x]` 완료. 상태가 바뀌는 ★그 순간★ 갱신한다. 세션 끝에 몰아서 하지 않는다.
3. 팀장이 "킵" 이라 하면 `📌 킵` 섹션에 넣고 ★착수하지 않는다.★ 설계 논의가 나와도 착수 지시가 아니다.
4. 팀장이 방향을 바꾸면 옛 항목을 지우지 말고 ★"GD 가 HH:MM 에 뒤집었다"★ 를 달아 둔다. 같은 키가 하루에 세 번 뒤집힌 적이 있다(2026-09-10 괄호키).
5. 내가 찾은 결함도 같은 목록에 ★"Steve 가 찾음"★ 표시로 넣는다. 팀장 것과 섞이면 누가 시켰는지 잃는다.
6. 내가 틀린 것도 적는다 (`### Steve 가 오늘 틀린 것`). 같은 실수를 반복하지 않는 장치다.

## TODO.md 모양 (프로젝트 저장소)

```markdown
# <프로젝트> — 작업 트래커
`[x]` 완료 · `[~]` 진행중 · `[ ]` 미착수

## 🎯 지향점 · 목표 (팀장 원문 인용)
## 🧱 정해진 구조 · 상시 기준
## 🔄 GD 실사용 피드백 (YYYY-MM-DD HH:MM KST) — <담당> 관리      ← 팀장 메시지 묶음마다 하나
   - [ ] 항목 — 팀장 원문 인용 · 사진 경로 · 원인(후보/확정) · 검증 기준
## 📌 킵 — 착수 안 함
## 🐛 별건 결함 — 검증 중 나온 것
## 🖐 팀장 손 검증 — 시험으로 못 재는 것
## ★ <담당> 이 오늘 틀린 것
```

## 보고 규율

- ★배달 성공 ≠ 일 시작.★ 팀원에게 위임했으면 ack 이 올 때까지 위임이 성립한 게 아니다. 평소 리듬(보통 1~2분)을 넘기면 짧은 핑, ★그래도 없으면 팀장에게 바로 알린다.★ 밤새 기다리지 않는다 (2026-09-11 7시간 공백).
- "다 처리했어?" 에는 ★숫자로★ 답한다 — "21건 중 19건". 남은 것과 막힌 이유를 같이.
- 내가 못 잰 것은 ★"못 쟀다"★ 라고 쓴다. 통과로 세지 않는다. 팀장 손 검증 목록으로 넘긴다.
- 공증본/배포본을 줄 때는 ★눌러볼 것★ 목록을 같이 준다 — 내가 못 잰 자리가 곧 팀장이 볼 자리다.

## 검증 규율 (프로젝트 PR 마다)

1. 고친 것을 도로 부수면 검사가 실패하는지 (뮤턴트). 통과 개수만으로는 안 받는다.
2. ★양쪽★을 잰다 — 되는 것만 재면 아예 못 쓰게 만들어도 통과한다.
3. 화면은 ★사진에서★ 잰다. CSS 에 적어놨다고 화면에 나오는 게 아니다.
4. 소스만 읽고 찾은 원인은 ★"후보"★. 재현 뒤에만 "확정".
5. 병합 메시지에 내가 잰 것 · 안 잰 것 · 틀린 것을 적는다.

## 인계 (다른 팀원에게 넘길 때) — 4줄
원문(팀장 지시 인용) · 진행 여부 · 저장소·브랜치 기준점 · 범위. 하나라도 빠지면 받는 쪽이 멈추거나 엉뚱한 데서 일한다. 브랜치 기준점을 안 주면 앞 수정을 조용히 되돌린다.
